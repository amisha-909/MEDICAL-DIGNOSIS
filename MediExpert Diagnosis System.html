What is an Expert System?

An expert system is an AI program that imitates the decision-making of a human specialist. It keeps expert knowledge in a knowledge base as IF–THEN rules, and uses an inference engine to match the facts you give it (your symptoms) against those rules to reach a conclusion.

How the AI Works

Six building blocks turn a list of symptoms into a reasoned suggestion.

🧩

Knowledge Representation

Medical expertise is written in a form a computer can use. Symptoms are stored as facts and medical knowledge is stored as production rules (IF–THEN). Each rule is a JavaScript object with conditions, a conclusion and advice.

📚

Knowledge Base

The knowledge base is the collection of all rules (0 rules in this project). It is separate from the reasoning code, so experts can add or edit rules without changing the engine.

🔀

IF–THEN Rules

A rule has an IF part (symptoms joined by AND) and a THEN part (possible condition).
IF fever AND cough AND cold THEN possible flu

⚙️

Inference Engine

The "brain" of the system. It takes the selected symptoms (working memory), checks every rule in the knowledge base, and uses forward chaining — moving from facts to conclusions.

🔍

Rule Matching

For each rule: score = matched conditions ÷ total conditions × 100. If all conditions are true the rule is triggered; if only some are true it is a partial match.

🎯

Decision Making

Rules scoring at least 60% (with 2+ matching symptoms) are ranked by score, then matched symptoms, then priority. The top rule becomes the best possible match, and its advice is shown.

Project Report

Rule-Based Medical Diagnosis Expert System

1. Project Introduction

Artificial Intelligence aims to make computers perform tasks that normally need human intelligence. One of the earliest successful branches of AI is the expert system: software that captures the knowledge of a human expert and uses it to solve problems in a narrow domain. This project builds a small medical expert system that suggests possible conditions from reported symptoms using IF–THEN rules and an inference engine, entirely in HTML, CSS and JavaScript.

2. Problem Statement

People often search symptoms online and receive confusing, unstructured information. Access to a doctor for every minor complaint is not always possible. There is a need for a simple, transparent system that organizes symptom information, shows which medical rules were matched, and gives basic safety advice — while making it clear that it does not replace a doctor.

3. Objectives

  • Represent medical knowledge as IF–THEN production rules.
  • Build an inference engine that matches symptoms to rules.
  • Calculate a rule-matching score and identify the best possible condition.
  • Explain the reasoning behind each result (explainable AI).
  • Provide precautions, next steps and emergency warnings.
  • Demonstrate Knowledge Representation and Expert Systems clearly.

4. Scope of the Project

In scope: 16 symptoms, 18 rules, simple conditions with mild to urgent severity, client-side processing, printable report. Out of scope: real clinical diagnosis, medicines or dosage, test results, medical history, uncertainty modelling, databases, or user accounts. All data stays in the browser's memory and is never saved.

5. AI Concepts Used

Knowledge Representation
Facts (symptoms) and production rules (IF–THEN) stored as structured JavaScript objects.
Expert Systems
Knowledge base + inference engine + user interface + explanation facility.
Rule-Based Reasoning
Conclusions are derived by applying rules to known facts.
Forward Chaining
Reasoning begins with the user's facts and moves toward conclusions.

10. Advantages and Limitations

Advantages
  • Transparent and explainable reasoning
  • Easy to add or change rules
  • Runs offline in any browser
  • No personal data stored
  • Fast, no training data needed
Limitations
  • Small knowledge base; many diseases missing
  • No probability or uncertainty modelling
  • Ignores symptom severity, history and tests
  • Cannot learn from new data
  • Not a replacement for a doctor

11. Future Enhancements

  • Add many more rules, built with the help of medical professionals.
  • Use certainty factors or Bayesian reasoning to handle uncertainty.
  • Ask follow-up questions (backward chaining).
  • Add symptom severity levels and medical history.
  • Support multiple languages and voice input.
  • Combine with machine learning for pattern discovery.

12. Conclusion

The project shows how knowledge representation and an expert-system inference engine can be combined to produce explainable decisions. By keeping medical knowledge in a separate rule base and showing which rules fired, the system is easy to understand, test and extend. It is an educational prototype that highlights both the usefulness and the limits of rule-based AI, and it reminds users that professional medical advice is always the final authority.
